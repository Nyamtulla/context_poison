Large language model agents answer from their
context~\cite{teng-2026-retrieval}. An attacker who controls one context
controls the answer~\cite{greshake-2023-not}. Two research communities study this
failure, and neither tests the other's work. Security researchers study context
an attacker changes on purpose; safety researchers study context that becomes
wrong on its own. The model cannot tell the difference.

We read \NCorpus{} papers in full and recovered every confirmed (defense,
attack) pair either community reports. Only a handful cross between them, and
\textbf{exactly \NSecDefVsSafetyAttack{} security defense has ever been
evaluated against a safety failure mechanism}. The two sides do not duplicate
each other. 
%Across \NMechanisms{} named mechanisms we find \NMechNameClash{} cross-community name collisions. 
They divide the problem instead. Security focuses on how the bad
text arrives and defends at ingestion. Safety deals with why the model believes it
and defends at reasoning. A defense at the reasoning stage judges text the
attacker has already chosen.

We then ran the experiments neither community has run. Our campaign covers
\NCampaignPairs{} pairs, each run from its authors' released code and weights
against an undefended model on the same items. No
context-reliance defense leaves the model better off than no defense at all.
One mechanism explains this. Each defense weighs the retrieved document
against the model's memory, and moving that weight relocates errors instead of
creating correct answers. One defense resists, by discounting context that
raises the model's uncertainty. A gradient-optimized passage that lowers
uncertainty removes \PctAcdRemovedGradient{}\% of its protection. We report
results for one model family and one retrieval setting.
