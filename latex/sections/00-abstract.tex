LLM agents answer from their context, so an attacker who controls the context
controls the answer. Two research communities study this failure, and neither
tests the other's work. Security researchers study context an attacker changes
on purpose; safety researchers study context that becomes wrong on its own. To the
model, both are text in the same context window.

We read \NCorpus{} papers in full and listed every case where a paper
tested a fix against a named problem. Only a handful test one community's
method against the other community's problem, and
\textbf{exactly \NSecDefVsSafetyAttack{} security fix has ever been
evaluated against a safety mechanism}. The two sides do not duplicate
each other. They divide the problem instead. Security studies how the bad text
arrives and defends where it enters. Safety studies why the model believes it
and intervenes where the model reasons. A fix that works on the model's
reasoning only sees text the attacker has already written.

We then ran these missing tests in both directions, each from the method's
own released code. Both directions fail, for opposite reasons.
\textbf{Methods built for honest mistakes decide how much to trust the
document, and that choice hands the answer to an attacker who wrote it.
Defenses built against attackers assume that wrong passages are few or
contain instructions, and an honest mistake can break both assumptions.}
When an out-of-date page is copied many times, a defense that votes across
passages gives the outdated answer more often than no defense at all. No
method we tested protects against both. A fix that does must rely on none of
these assumptions. We report results for models of 7 to 14 billion
parameters, with one dataset per experiment.
