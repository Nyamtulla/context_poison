Large language model agents answer from retrieved documents. An attacker who
controls one document controls the answer. Two research communities study this
failure and neither tests the other's work. Security researchers study context
an attacker changes on purpose; safety researchers study context that becomes
wrong on its own. The model cannot tell the difference.

We read \NCorpus{} papers in full. \NAnalysed{} name an attack or a defense,
and from those we recover \NPureRegimePairs{} confirmed (defense, attack)
pairs. Only \NCrossCommunityPairs{} (\PctCrossCommunity{}\%) cross between
the communities, and one direction is all but closed:
\textbf{\NSecDefVsSafetyAttack{} security defense has ever been evaluated
against a safety failure mechanism}, against \NSecDefSecAttack{} evaluated
against security attacks. The two sides do not duplicate each other. Across
\NMechanisms{} named mechanisms we find \NMechNameClash{} cross-community
name collisions. They divide the problem instead. Security names how the bad
text arrives and defends at ingestion. Safety names why the model believes it
and defends at reasoning, \NDefPtReasoningSafety{} defenses against
\NDefPtReasoningSec{}. A defense that reasons better about a document sits
downstream of whoever wrote it.

We then ran the experiments neither community has run. The campaign covers
\NCampaignPairs{} pairs across \NCampaignImpl{} implementations and
\NCampaignEpisodes{} scored episodes. Every method runs from its authors'
released code and weights, against an undefended model on the same items. No
context-reliance defense leaves the model better off than no defense at all.
One mechanism explains this. Each defense weighs the retrieved document
against the model's memory, and moving that weight relocates errors instead of
creating correct answers. One defense resists, by discounting context that
raises the model's uncertainty. A gradient-optimized passage that lowers
uncertainty removes \PctAcdRemovedGradient{}\% of its protection. We report
results for one model family and one retrieval setting.
