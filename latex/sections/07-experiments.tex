\section{The platform}
\label{sec:experiments}

Section~\ref{sec:emptycell} ends at a cell nobody has filled. This section
and the next answer RQ2, and this one is the instrument we built to do it: a uniform harness that runs a published
defense against a published attack under one protocol, with the controls fixed
before any run.

\subsection{Pair selection}

We did not pick case studies by familiarity. The taxonomy picks them.

A (defense, attack) pair is a candidate under two conditions. The defense and
the attack must occupy the same taxonomy cell, which means the content enters
through the same channel and causes the same consequence. And no paper in the
corpus may report having run them together. If a defense repairs a failure that arrives through retrieval and
corrupts answers quietly, and an attack arrives through retrieval and corrupts
answers quietly, then the defense ought to apply. The taxonomy says so. Nobody
had checked.

\textbf{We are not proposing new defenses.} Every method we run is published,
and every attack we run is published. The contribution is the pairing.

\textbf{The campaign is deliberately cross-community.}
\NOursCrossPairs{} of our \NOursPairs{} retrieval-cell pairs put a safety method against a security attack, which is \PctOursCross{}\% against
the literature's \PctCrossCommunity{}\%. \NRagImplSafety{} of our \NRagImpl{} retrieval defense
implementations are knowledge-conflict methods from the safety literature,
run against corpus poisoning, PoisonedRAG~\cite{zou-2024-poisonedrag} and
BadRAG~\cite{xue-2024-badrag}. That is the empty column
of Figure~\ref{fig:transferlit}, populated.

Of the \NRagPairsKeyed{} pairs we ran in the retrieval cell, counted at
registry-name level, \textbf{\NRagPairsNovel{} are absent from the
\NPairsComposite{} pairs the literature reports}. The two that are not novel
are COIECD against knowledge conflict and RobustRAG~\cite{xiang-2024-certifiably} against PoisonedRAG, which
those papers tested themselves and which we re-ran as controls.

\subsection{The reconstruction standard}

Every number we report comes from running a defense's own released code and
weights. We never cite a paper's reported numbers as evidence about that
paper's method. Where a harness had to be adapted to our data, we adapted the
harness and left the method and the evaluation rubric untouched. Where an
author's rubric and ours differed, we used the author's.

This standard cost us coverage and we report the cost. Of the defenses we tried
to run, several could not be evaluated at all, and the reasons are themselves a
finding. One ships a pipeline whose datasets the authors state they cannot
release. One requires a four-stage data build whose intermediate format is
undocumented. Two execution-stage defenses do not run reliably on any
freely-available open-weight model. We record these as roadblocks rather than
as failures of the method, and they belong in Section~\ref{sec:discussion}.

\subsection{Pre-registered experimental rules}

A negative result is easy to produce by accident. Four rules guard against
that, and we fixed all four before any run.

\textbf{The control fires first.} A defense that is broken in our hands
tells us nothing about transfer, so before any transfer number we check that
the method still does on clean context what its authors say it does. The
check is directional and it is per method, because the thing each paper
claims is not the same quantity. ParamMute reports a gain in context
recall, not in accuracy. CK-PLUG claims no accuracy gain at all: its
contribution is a knob that moves memorization rate while accuracy is held,
so its control fires on that rate instead. ACD~\cite{kim-2024-adaptive} states its improvement
without a figure. SCR's own authors report it underperforming their
baseline on Llama-3-8B, the model we run it on, so on this model there is no
published gain to reproduce and agreement with them means moving the same
way they report. We therefore check the direction, on the metric that
paper uses, for the model it used, and we record for every method which
quantity its control was read on. Where no comparable published figure
exists we say so rather than manufacture a threshold.

One defense fails the check outright and we report it as not reportable
rather than as defeated. FaithfulRAG~\cite{zhang-2025-faithfulrag} needs
structured output support that open weights do not provide in its harness,
and the ablated variant that does run shows none of its own benefit.

\textbf{The attack works first.} If the attack does not degrade the undefended
arm in the same run, the defended arm means nothing. Every result below is
reported next to an undefended arm measured on the same items at the same doses
with the same scorer.

\textbf{Effects are gated on a minimum detectable change.} For each run we
compute the smallest difference detectable at the given sample size with
$\alpha = .05$ and power $.80$. Differences below it are reported as "no
resolvable effect", never as "no effect". This matters because several
published claims in this area rest on differences that a run of their size
cannot resolve.

Attacks are not adapted to the defenses they meet, with one
exception reported in Section~\ref{sec:results2}. Carlini's critique of the
DeepSec platform~\cite{carlini-2019-critique} identifies this as the error that
invalidated DeepSec's defense rankings, so we state the consequence precisely
rather than leaving it implicit. An attack that is not built for a defense and
defeats it anyway is a lower bound on attack strength: if the
cheapest payload wins, an adapted one also wins. So non-adaptive evaluation is
conservative for a claim that a defense fails, and invalid for a claim that one
holds. Every failure we report is of the first kind. The single resistance
result we report is of the second, and we test it adaptively rather than
asserting it.

Predictions were written into the runner scripts and committed to version
control \emph{before} each run, and they ship with the artifact.

\subsection{What we ran}
\label{sec:whatweran}

\paragraph{Environment.}
Every run in this paper used one NVIDIA RTX A6000 with 48\,GB, driver
535.274.02 and CUDA 12.8, under Python 3.10.12, PyTorch 2.10.0 and
\texttt{transformers} 5.5.0. Two defenses cannot use that last version. ACD's
released decoder imports symbols that \texttt{transformers} removed after
4.44, which its own README pins, so it runs in a separate dependency set.
CK-PLUG ships its own 4.49 fork and its README says to install it. We record this
because it is a result as much as a configuration detail. The defenses in a
single cell of this taxonomy cannot share one Python environment. That is the
reproducibility problem of Section~\ref{sec:discussion}, one layer further
down. The released artifact builds each set and verifies it.

The campaign covers two cells.

The retrieval cell pairs defenses built for knowledge conflict against
attacks built to poison a retrieval corpus. The victim model is
Llama-3-8B-Instruct~\cite{grattafiori-2024-llama3} or
Mistral-7B-Instruct~\cite{jiang-2023-mistral}, depending on what each defense
released. The data is CoConflictQA~\cite{huang-2025-parammute} over Natural Questions, and open Natural
Questions for the attacks that need a retrieval pool.

Those defenses turn the same dial. ACD decodes from the no-context
distribution and pulls it toward the with-context one by a weight computed
from entropy. CK-PLUG~\cite{bi-2025-parameters} interpolates the two
distributions under a single parameter. ParamMute~\cite{huang-2025-parammute}
suppresses the feed-forward layers that carry parametric memory, forcing the
model onto the retrieved text. SpARE~\cite{zhao-2024-steering} and
SHIFT~\cite{li-2026-shift} steer along a context-faithfulness direction in
activation space. COIECD~\cite{yuan-2024-discerning} detects a conflict
between the two sources and pushes toward the context.
SCR~\cite{huang-2024-trust} makes the same trade through prompting rather
than decoding. Each changes \emph{how much} the model leans on retrieved
text. None asks \emph{which} retrieved text deserves trust.

The agent cell pairs ingestion-stage and execution-stage defense
techniques against prompt-injection attacks inside the AgentDojo banking
suite~\cite{debenedetti-2024-agentdojo}, with a Qwen2.5-14B-Instruct~\cite{qwen-2024-qwen25} agent.

In total we executed \textbf{\NCampaignPairs{} distinct (defense, attack)
pairs across \NCampaignImpl{} defense implementations, over
\NCampaignEpisodes{} scored episodes}: \NRagPairs{} pairs and \NRagEpisodes{}
episodes in the retrieval cell, \NAgentPairs{} pairs and \NAgentEpisodes{}
episodes in the agent cell.
The two episode counts are not comparable units. An agent episode is a complete
multi-step tool-use trajectory. A retrieval episode is one scored answer.

Holding the items fixed is also what makes the payload comparison in
Section~\ref{sec:payloadclasses} mean anything. Within a cell the items, the
dosing and the scorer never change; only the form of the planted passage does.
Carlini's fifth criticism of DeepSec is that it compared defended and
undefended rates computed on different item sets, which makes the numbers
incomparable rather than merely noisy~\cite{carlini-2019-critique}. We checked
this mechanically rather than by inspection: across every result registry,
no run compares two arms measured on different items.

The one place the item set narrows is the distractor payload, and it narrows
for both arms together. It is defined on 781 of CoConflictQA's 1,409 items. An item
qualifies on two conditions. Its remembered answer must appear verbatim in its
own evidence sentence, so that the substitution needs no rewriting. And its
question type and answer magnitude must admit at least three candidate
distractors, so that the planted answer is a plausible example of its kind
rather than an absurdity a reader would dismiss. Every arm in those runs, including the undefended and no-retrieval
arms, is measured on that same subset.

\subsection{Payload classes}
\label{sec:payloadclasses}

\paragraph{Which items.}
The retrieval cell evaluates every item whose context is at most 2000
characters. The cut is on context length alone, never on an outcome, and it is
applied once and then frozen, so every defense and every payload meets the
same items. Its purpose is to keep contrastive-decoding defenses, which hold
two forward passes of the model at once, inside the memory of one card at a
batch size that the whole cell can share. The one narrower slice is the
distractor payload, and Section~\ref{sec:provenance} gives both of its
conditions.

Within the retrieval cell we hold the items, the dosing and the scorer fixed
and vary only the \emph{form} of the planted passage. A defense that behaves
differently across them tells us which property it is actually keying on.

Corpus poisoning~\cite{zhong-2023-poisoning,su-2024-corpus} optimizes a
token sequence to be retrieved for many queries. The resulting passage is
incoherent to a human reader. It attacks by displacing honest documents.

False evidence plants a fluent, well-formed sentence that asserts the
wrong answer the model itself would have given from memory. It is drawn from
CoConflictQA and reads like an ordinary encyclopaedia sentence. It attacks by
agreeing with the model's prior.

Distractor evidence is the same fluent sentence with one word
changed, asserting a third answer that is neither the truth nor the model's
prior. It is not a stronger attack; it is a measuring instrument, and
Section~\ref{sec:distractor} explains why it was necessary.

An adaptive distractor is the same payload in whichever surface form
minimizes the specific quantity one defense's rule measures
(Section~\ref{sec:results2}).

Provenance is in Table~\ref{tab:provenance} and one case is worth drawing
out. False evidence is the \texttt{parametric\_evidence} field that ships
inside CoConflictQA, the benchmark the ParamMute authors released themselves,
so one of the defenses we break is broken with a field from its own dataset.
The distractor and the adaptive distractor are ours. Both are edits of that
same field rather than new attack techniques. The distractor changes one word.
The adaptive version changes only the surface form around an unchanged
claim.

\paragraph{Two dosing protocols, and why both exist.}
CoConflictQA gives one context passage per item, so there is no ranked list to
dose. On it we cut the context into fixed-length chunks and replace a
fraction: 10\%, 50\% and 100\%, with a clean arm at 0\%. Open Natural
Questions ships a retrieval pool, so there we dose the way the attack papers
dose, replacing $j$ of the top ten retrieved passages for $j$ in $\{0, 1, 2,
3, 5, 10\}$. The second is the attacks' own construction and the first is
ours. That distinction matters, because a protocol we invented is a place
where our own choices can decide a result, so each number below reports which
protocol produced it. Section~\ref{sec:regime} runs entirely under the
attacks' own dosing.

Every result file carries a fingerprint of the payload it was produced with,
so a run cannot be read under the wrong attack label.
