\section{Introduction}

An LLM agent reads from many places. It reads retrieved documents, the output
of the tools it calls, the descriptions of the tools themselves, files and
skills it loads, messages from other agents, and its own stored memory. All of
this arrives in one context window, and the model treats it as one body of
text. The model has no reliable way to tell which part of that text is
trustworthy and which part is not.

Two research communities study what goes wrong when untrustworthy content gets
in, and they use different words for it.

The security community studies content that an attacker placed there on
purpose. It names attacks such as indirect prompt injection, retrieval
poisoning~\cite{zou-2024-poisonedrag,zhong-2023-poisoning} and memory
backdoors, and it publishes defenses against
them~\cite{xiang-2024-certifiably,liu-2025-datasentinel,an-2025-ipiguard}.
Success means the attacker fails to achieve a goal.

The machine learning community studies content that became wrong without any
attacker. It names mechanisms such as lost-in-the-middle~\cite{liu-2023-lost},
context rot, and knowledge conflict between a retrieved passage and what the
model already learned~\cite{xie-2023-adaptive}, and it publishes fixes for
them~\cite{huang-2025-parammute,bi-2025-parameters,yuan-2024-discerning}.
Success means accuracy goes up.

The two communities describe the same underlying failure. A passage the model
should not trust enters the context window and changes the output. Only the
provenance differs. The model sees tokens either way.

\paragraph{Why the split matters.}
A vocabulary split would be harmless if it were only a naming difference. It is
not. A fix designed for the accidental case is evaluated on average-case
benchmarks, because nothing is adapting to it. A defense designed for the
adversarial case is evaluated against a worst case, because something is. When
the two communities do not read each other, a method can be published,
adopted and cited without anyone asking whether it survives the other
community's threat model. We show that this has happened, that it has happened
at scale, and that for one common family of methods the answer is that it does
not survive, for a reason that is visible in the method's own design.

\paragraph{What an SoK must add.}
A systematization is judged on whether it gives the community a viewpoint it
did not have, not on whether it summarizes well. We make four moves beyond
summary. First, we measure how separate the two communities are, and find a
cell of the cross-testing matrix that is empty: no security defense in our
corpus has ever been evaluated against a machine learning failure mechanism.
Second, we run the experiments that cell is missing, on the authors' own
released code and weights. Third, we explain the result, which turns out to be
one mechanism rather than a list of failures. Fourth, we show it survives an
attacker who reads the defense and optimizes against it.

The second and third moves are the part a survey normally cannot do, and they
are what turns a coverage gap from an observation into evidence.

\paragraph{Contributions.}
\begin{itemize}
\item \textbf{The empty cell.} Across \NPureTrackPairs{} confirmed (defense,
  attack) pairs recovered from \NCorpus{} papers read in full, only
  \NCrossCommunityPairs{} (\PctCrossCommunity{}\%) cross between the two
  communities, and \textbf{no security defense has ever been evaluated against
  a machine learning failure mechanism} (Section~\ref{sec:emptycell}). The
  supporting measurements are a joint taxonomy over channel, intent and
  consequence, of which \PctCubeEmpty{}\% of cells hold no paper from either
  side; a census of \NMechanismsBench{} named mechanisms and \NDefenses{}
  named defenses, coded by the threat model each was actually validated
  against rather than the one it claims; and citation rates of
  \PctSecCitesML{}\% and \PctMLCitesSec{}\% in the two directions
  (Section~\ref{sec:literatures}).

\item \textbf{A platform, and \NCampaignPairs{} pairs run on it} across
  \NCampaignImpl{} implementations and \NCampaignEpisodes{} scored episodes,
  each from its authors' released artifacts under an attack-works-first
  control and a fixed detectability threshold
  (Section~\ref{sec:experiments}). \NOursCrossPairs{} of our \NOursPairs{}
  retrieval-cell pairs cross the community boundary, against
  \PctCrossCommunity{}\% of the literature's.

\item \textbf{One mechanism, not a list of failures.} Context-reliance
  defenses relocate correctness rather than creating it: what they take from
  the model's memory the attacker receives, and what they take from the
  attacker memory receives. Neither direction moves probability mass toward
  the real document, because the axis these methods arbitrate on does not
  contain the distinction an attacker violates
  (Sections~\ref{sec:results}, \ref{sec:distractor}).

\item \textbf{An adaptive attack} on the one defense that resisted, built
  against the single quantity its rule measures. It removes 58\% of the
  protection and drives accuracy onto the undefended arm
  (Section~\ref{sec:results2}).

\item \textbf{Three controls} the literature omits, each of which changed a
  conclusion in our own work (Section~\ref{sec:results2}).
\end{itemize}
