\section{Introduction}

An LLM agent reads from many places. It reads retrieved documents and the output of the tools it calls. It reads the descriptions of those tools, the files and skills it loads, and messages
from other agents. It also reads its own stored memory~\cite{chu-2026-systematic,ma-2025-safety}. All of this arrives in one context window, and the model treats it as one body of
text. The model has no reliable way to tell which part of that text is trustworthy and which part is not~\cite{greshake-2023-not}.

It helps to picture the context window as a body of water fed by a fixed set
of inflow streams. Whatever enters through any stream mixes into the same body
and affects everything downstream, whether it was dumped in deliberately or
arrived as runoff. The question this paper answers first is simply, how
many streams are there, and how many consequences may arise because of this pollution? 

Two research communities study what goes wrong when untrustworthy content gets
in, and they use different words for it. The security community studies content that an attacker placed there on purpose. It names attacks such as indirect prompt
injection~\cite{greshake-2023-not}, retrieval
poisoning~\cite{zou-2024-poisonedrag,zhong-2023-poisoning} and memory
backdoors~\cite{dash-2026-untrusted}, and it publishes defenses against
them~\cite{xiang-2024-certifiably,liu-2025-datasentinel,an-2025-ipiguard}.
Success means the attacker fails to achieve a goal.

The AI/ML community studies content that became wrong without any
attacker. It names mechanisms such as lost-in-the-middle~\cite{liu-2023-lost} and
context rot~\cite{xia-2026-diagnosing}. It also names knowledge conflict, where a retrieved passage
disagrees with what the model already
learned~\cite{xie-2023-adaptive}. It publishes fixes for
them~\cite{huang-2025-parammute,bi-2025-parameters,yuan-2024-discerning}.
Success means accuracy goes up.

The two communities describe the same underlying failure: a passage the model
should not trust enters the context window and changes the output. Only the
provenance differs; the model sees tokens either way. The difference is not merely one of vocabulary. If it were, a reader could
translate between the two communities and lose nothing. They differ in
something load-bearing: what counts as a successful evaluation? The AI/ML community measures a fix for the accidental case on an average-case
benchmark, because nothing adapts to it. The security community measures a defense for the
adversarial case against the worst case, because something does. Those are not two styles
of the same test. A method can pass the first test convincingly and fail the second one
completely. Neither community's publishing process catches this, because each
reviews against its own convention.

So the field publishes, adopts, and cites a method without anyone asking
whether it survives the other community's test. That is a testable claim about the literature, not a complaint about it. We
test it by reading both literatures under one taxonomy and recovering every
experiment either side has run. The test finds a gap. We then run the
experiments that fall in it to answer the following research questions.

\paragraph{Research questions.}
\begin{description}
\item[RQ1] \textbf{Are the two communities reinventing the wheel?} We read
  \NCorpus{} papers from both sides under one scheme, compare what each
  community names for the same failure, and date who reached each problem
  first (Sections~\ref{sec:literatures}, \ref{sec:parallel}).
\item[RQ2] \textbf{Is there a region of the problem that neither community
  has tested?} We recover every (defense, attack) pair reported by the
  \NAnalysed{} papers that name a technique (Section~\ref{sec:literatures}).
\item[RQ3] \textbf{Does a defense built for one community's problem transfer
  to the other's?} We execute the pairs the literature skipped, from the authors'
  released code and weights (Sections~\ref{sec:experiments},
  \ref{sec:results}).
\item[RQ4] \textbf{Is failure a property of individual methods or of a design
  choice they share?} We build a payload that separates the explanations
  rather than maximizes damage (Section~\ref{sec:distractor}).
\item[RQ5] \textbf{Does that explanation survive an adaptive attacker?} We
  build two optimizers against the one method that resisted
  (Section~\ref{sec:adaptive}).
\end{description}

Others have separately surveyed both literatures before: the
security side
repeatedly~\cite{dehghantanha-2026-sok,chu-2026-systematic,jiang-2026-sok},
and the AI/ML side on its own terms as a problem of knowledge
conflict~\cite{xu-2024-knowledge}. We borrow from those surveys rather than
compete with them. But the last three research questions are the ones a survey normally
cannot answer, and they are what turns a coverage gap from an observation into
evidence. What is new here is that one corpus, one taxonomy, and one harness
span both. A survey of one piece of literature cannot report a gap that the
other literature defines. Our taxonomy locates missing experiments across both literatures and names
the defense and the attack in each, which are published methods with released
code. To our knowledge this is the first evaluation in which published defenses from one of these
communities meet published failure mechanisms from the other.

A negative result is easy to produce by accident. Four rules fixed before any
run guard against that, and Section~\ref{sec:experiments} states them in
full.

\paragraph{Scope.}
Three limits are worth stating before the contributions rather than after
them. Our retrieval experiments use one item set for each setting. They measure
what a generator does with poisoned context, not how hard a retriever is to
poison. Most of them use one model family at one size. Our own model control shows
that a different model gives different outcomes. The numbers therefore hold
for models of that class, not in general. Every attack in the campaign, except the two in
Section~\ref{sec:adaptive}, knows nothing of the defense it meets. That bounds
attack strength from below. It gives conservative evidence when a defense
fails, and no evidence at all when one holds. Section~\ref{sec:threats} gives the full list.

\paragraph{Contributions.}
\begin{itemize}
\item \textbf{Not the wheel, but half of it (RQ1).} The two communities are
  not duplicating each other's work. They are dividing the problem. One side
  studies how the bad text arrives and defends where it enters; the other
  studies why the model believes it and defends where it reasons.
  \textbf{Duplicated effort would still leave two working defenses; halves
  that never meet leave neither} (Section~\ref{sec:parallel}).

\item \textbf{The region nobody tests (RQ2).} Of every confirmed (defense,
  attack) pair either community reports, only a handful cross between them,
  and \textbf{a security defense has been evaluated against an AI/ML failure
  mechanism exactly \NSecDefVsSafetyAttack{} time}
  (Section~\ref{sec:emptycell}).

\item \textbf{A platform, and \NCampaignPairs{} pairs run on it (RQ3).} Every
  method executes from its authors' released code and weights, against an
  undefended arm on the same items, under controls fixed before any run
  (Section~\ref{sec:experiments}).

\item \textbf{One mechanism, not a list of failures (RQ4).} The defenses that
  fail here share a design: they weight the retrieved text against the model's
  memory. That relocates correctness rather than creating it. What they take
  from memory the attacker receives, and what they take from the attacker
  memory receives. Neither direction moves anything toward the real document
  (Sections~\ref{sec:results}, \ref{sec:distractor}).

\item \textbf{Two adaptive attacks on the one defense that resisted (RQ5).} It
  loses \textbf{\PctAcdRemovedGradient{}\%} of its protection to an attacker
  who reads its rule, which prices the method rather than dismissing it
  (Section~\ref{sec:adaptive}).

\item \textbf{Three controls the literature omits}, each of which decides how
  a result reads: a no-retrieval baseline, an abstention axis, and a second
  base model (Section~\ref{sec:results2}).

\item \textbf{A runnable artifact.} Every attack and defense executes from its
  authors' released code at a pinned commit, verified unmodified; the harness,
  the payloads and the full census ship with it.
\end{itemize}
