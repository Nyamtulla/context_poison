\section{Introduction}

An LLM agent reads from many places: retrieved documents, the output of the
tools it calls, the descriptions of those tools, the files and skills it
loads, messages from other agents and its own stored
memory~\cite{chu-2026-systematic,ma-2025-safety}. All of it arrives in one
context window, and the model has no reliable way to tell which part is
trustworthy~\cite{greshake-2023-not}.

Two literatures study what goes wrong when untrustworthy content gets in.
Security papers study content that an attacker placed there on purpose. They
name attacks such as indirect prompt injection~\cite{greshake-2023-not},
retrieval poisoning~\cite{zou-2024-poisonedrag,zhong-2023-poisoning} and memory
backdoors~\cite{dash-2026-untrusted}, and publish defenses against
them~\cite{xiang-2024-certifiably,liu-2025-datasentinel,an-2025-ipiguard}.
Success means the attacker fails. Safety papers study content that became
wrong without any attacker. They name causes such as
lost-in-the-middle~\cite{liu-2023-lost}, context
rot~\cite{xia-2026-diagnosing} and knowledge conflict, where a retrieved
passage disagrees with what the model already learned~\cite{xie-2023-adaptive},
and publish fixes for
them~\cite{huang-2025-parammute,bi-2025-parameters,yuan-2024-discerning}.
Success means accuracy goes up.

Both describe the same failure: a passage the model should not trust enters
the context and changes the output. They differ in what counts as a
successful evaluation. Safety papers measure a fix on average-case
benchmarks, because an accident does not adapt to the fix. Security papers
measure a defense against the worst case, because an attacker does. A method
can pass the first test and fail the second, and because each literature
evaluates by its own convention, a method is rarely tested against the
other's problem. This paper measures that gap and runs the missing tests.

\paragraph{Research questions.}
\begin{description}
\item[RQ1] \textbf{Do the two literatures duplicate each other's work?} We
  read \NCorpus{} papers from both sides under one taxonomy, recover every
  (fix, cause) pair they report, and compare where each literature's fixes
  act (Section~\ref{sec:literatures}).
\item[RQ2] \textbf{How does each literature test its fixes, and what does that
  require of a test across them?} We code the evaluation design of
  \NDesignFixes{} retrieval fixes from their full text
  (Section~\ref{sec:testing}).
\item[RQ3] \textbf{Does a fix built for one literature's problem survive the
  other's?} We run safety fixes against attacks, each on the input it was
  built for, from its authors' released code and weights
  (Section~\ref{sec:results}).
\item[RQ4] \textbf{Does the failure belong to individual methods, or to an
  assumption their designs share?} We plant passages that tell the
  explanations apart and attack the one fix that resisted with an attacker
  who knows its rule (Section~\ref{sec:results}).
\item[RQ5] \textbf{Taken together, do the two literatures solve context
  poisoning?} We combine where each literature's fixes act with an agent
  experiment that measures which stage holds (Section~\ref{sec:together}).
\end{description}

RQ2 also explains what RQ3 cannot yet answer. Security defenses that vote
across retrieved passages need a ranked set, and the safety literature's
datasets give one passage per question, so the second direction, security
defenses against honest mistakes, cannot be run fairly on either side's
data. We build the data it needs (Section~\ref{sec:dataset}).

\paragraph{Contributions.}
\begin{itemize}
\item \textbf{We map both literatures onto one taxonomy.} Over \NCorpus{}
  papers read in full, we place every named cause and fix by channel,
  consequence and literature, and find that the two divide the problem:
  security fixes act where text enters the context, safety fixes where the
  model reasons about text already inside (RQ1).

\item \textbf{We identify the region neither literature has tested.} Of
  \NPureRegimePairs{} tested (fix, cause) pairs, \NCrossCommunityPairs{}
  cross between the literatures, and the papers cite each other's work far
  less than their own (RQ1).

\item \textbf{We show how each literature tests, and what a fair test across
  them needs.} The number of passages a fix is tested on follows the question
  it asks. What separates the literatures is what the bad text competes with,
  whether results are split by what the model knew, and whether the attacker
  adapts (RQ2).

\item \textbf{We trace why safety fixes fail against an attacker.} Each one
  decides how far to trust the document, and that choice hands the answer to
  whoever wrote it. The one fix that resisted did so because of the form of
  the attack text, and an attacker who knows its rule removes most of that
  protection (RQ3, RQ4).

\item \textbf{We show that the two literatures, taken together, do not close
  the gap.} Their fixes act at different stages, no published work joins
  them, and in an agent experiment only defenses that act before the model
  reads the bad text, or before it acts, hold (RQ5).

\item \textbf{We build a dataset both literatures can run on.} Each false
  claim appears as one passage and inside ranked sets, in an attacker version
  and in versions of real honest mistakes, with every planted passage checked
  to state its false answer (Section~\ref{sec:dataset}).
\end{itemize}

\paragraph{Scope.}
Each fix runs on one base model of 7 to 14 billion parameters, chosen by what
its authors released. We plant bad passages into the context rather than
attack the retriever, so the numbers describe what a model does with bad text
once it has it. The attacks we run were not designed against the fixes they
meet, except the two we build against one fix: if a fix loses to such an
attack it would also lose to a stronger one, and if it holds that shows
little.

\paragraph{How the paper reads.} Section~\ref{sec:background} defines the
terms and the threat model. Section~\ref{sec:literatures} answers RQ1 and
Section~\ref{sec:testing} RQ2. Sections~\ref{sec:experiments}
and~\ref{sec:setup} describe the platform and what it ran, and
Section~\ref{sec:results} answers RQ3 to RQ5. Section~\ref{sec:dataset}
presents the dataset. Sections~\ref{sec:discussion} and~\ref{sec:threats}
give the recommendations and the limits. We release the code, the coded
papers and the dataset.
